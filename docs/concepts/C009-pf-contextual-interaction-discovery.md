## 1. 问题与证据边界

固定 Cell、项目快照、执行策略及其他坐标后，同一坐标出现较低 PASS、较高 Probe Rejection，
是 C004 研究的单轴非单调。改变其他坐标后，同一个目标版本的结果改变，则涉及上下文交互。
后者不能用前一个 Slice 的边界解释，也不能把不同上下文的结果拼成 hole。

E014 中，Jinja2 2.10.3 在包含 MarkupSafe 1.1.1 的已提交向量通过，在新 baseline 的
MarkupSafe 3.0.3 上失败，并有对应 import 诊断。这支持调查上下文与搜索顺序；两轮的其他条件
也有变化，尚不能把历史记录当作仅改变 MarkupSafe 的受控配对重验。

“局部非单调、交互稀疏、连通分量小”是工作假设，不是已证明的项目分布。本文研究如何在证据与预算
允许时寻找局部改进，不承诺全局最低向量，也不将一般多维问题简化为必然可解的二维问题。

## 2. 候选触发条件

可研究在一个坐标未发现任何 strictly-lower PASS 时启动探索；当前 incumbent 的 `slice_high`
即使 PASS，也不计入 lower-PASS。触发前应保留下列区别：

| 状态 | 研究含义 |
| --- | --- |
| 合法更低候选为空 | 没有可下降空间，不是失败证据 |
| 存在未探候选，但尚未发现 lower-PASS | 搜索覆盖不足，不能称全部候选失败 |
| 完整合法更低候选集均有合格 Rejection | 当前 Slice 无 lower-PASS，不证明换上下文仍失败 |
| INDETERMINATE 或同点直接结果冲突 | 执行/证据问题，不作为交互或 hole 的普通输入 |
| `slice_high` 自身未能维持 PASS | incumbent invariant / recovery 问题，先按现行契约处理 |

这只是预算触发启发式；已经找到部分 lower-PASS 的坐标也可能因交互而错过更低点。
本文不修改现行停止、恢复或 apply 条件。

## 3. Contextual re-search 与受控证据

研究候选流程以具有直接 PASS 的原始向量 H 为起点，固定除 A、B 外的全部条件：

1. 对每个候选 B，从同一 H 探索 B 的下降，保存所观察到的 lower-PASS 上下文 b。
2. 对每个这样的 b，以 `(A=H_A, B=b, rest=H_rest)` 重新搜索 A，而非只拿一个预先选定的失败版本 Va 去试。
3. 若找到直接 PASS 的较低 a，重验 `(A=a, B=H_B, rest=H_rest)`。
4. 只有后一向量得到合格 Rejection，且身份、解析规则与其余上下文一致，才形成该局部范围内的交互证据。
   若 PASS，则只是原搜索未发现该点；若 INDETERMINATE 或冲突，则证据未闭合。

每条证据保存两个精确向量、Cell、源码与执行身份、实际解析环境、结果及原始引用。固定解析规则下，
传递依赖可能随直接向量变化；这种配对支持向量上下文依赖，不自动证明某个包的直接因果机制。
历史观察的存储与可否免重验由 C008 单独研究；记录存在不等于准入。

独立从 H 产生的探索分支不能直接拼接成 current。组合向量需要自身的完整合格验证；
精确 PASS 也不自动授权区间声明或最终 apply。

该流程仍有盲区：如果只有同时降低 A、B 才能 PASS，而从 H 单独降低任何一个都失败，步骤 1
找不到可用的 b。更高阶联合下降也可能如此。未发现配对证据不能证明独立，不能据此永久剪掉联合区域。

## 4. 图、局部 block 与粗到细发现

可把局部配对证据组织成图，以小连通分量提出 block 搜索任务。边必须携带 context、版本区域与证据，
不能仅留下无条件的包名关联。连通分量是候选任务范围，不是已证明独立的分解；未探边、高阶交互与
上下文改变均可能使该分解不完整。

先设定 block 大小、总调用和墙钟预算，再决定局部联合候选生成方式。超限时保存已见事实并报告
未完成范围，不能把“预算内没有找到”升级成“不存在更低 PASS”。本 Concept 不要求全 Cartesian 枚举。

`major → minor → patch` 可作为交互定位的候选顺序：先以代表版本探测，再细化可疑区域。
粗层没有发现交互不能排除细层局部交互；代表 PASS/FAIL 也不能代表整个系列。最终声明需要的 finer
oracle 证据不能被粗层省略。该方案属于本文的子问题，不恢复通用多分辨率 floor 搜索，也不预设成本收益。

算法产生任务，执行层限制资源。现有 Cell 调度与 static/verifier 许可池仍由 D008 定义；
更广泛的资源调度是独立性能方向，不是本研究的前置实现。

## 5. 下一步与进入 Design 的条件

先在固定身份下复证 E014 相关精确向量，再比较便宜的坐标顺序调整、延后重试与多 sweep，判断是否已能
解决观察案例。随后才比较 contextual re-search、局部 block 和 coarse-to-refine 的增量收益。
已知异常案例与代表性项目分组报告，不能用专挑的反例估计普遍交互率。

进入 Design 前至少需要：可复现配对证据；相对便宜对照的点质量与实际执行成本；检测漏项和预算终态；
context 改变后的证据准入；精确结果、声明投影和 apply 的资格边界。若这些仍只能靠不稳定推断连接，
保留研究，不以文档整理选定产品算法。
