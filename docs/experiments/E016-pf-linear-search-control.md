- **性质：** 非规范性实验协议；仅记录待执行方法，不授权产品实现或启动真实运行
- **证据位置：** 本文件保存协议；尚无运行产物、日志、run-id 或结果目录
- **关联：** [C004](../concepts/C004-pf-evidence-respecting-optimistic-monotone-search.md)、[C008](../concepts/C008-pf-cross-run-evidence-store.md)、[C009](../concepts/C009-pf-contextual-interaction-discovery.md)
- **历史背景：** [E011](E011-pf-optimistic-search-exploration.md)、[E012](E012-flask-complete-search.md)、[E013](E013-requests-complete-search.md)、[E014](E014-mkdocs-complete-search.md)、[E015](E015-pf-self-bootstrap-complete-search.md)

未进行采集或算法回放，不存在 binary/linear 比值、hole 频率或收益结论。

## 1. 两类问题分别测量

| 对照 | 固定条件与做法 | 可回答的问题 |
| --- | --- | --- |
| A：固定 Slice 真值采集与回放 | 固定其他坐标和环境，完整扫描明确评价域内全部候选，再离线回放各策略 | 序列非单调、hole 分布、相同问题的调用成本与最低直接 PASS 差距 |
| B：独立整轮 coordinate linear 对照 | 同一起始 baseline 与 policy，两种算法各自按其轨迹更新 current | 整轮成本、最终向量、sweep、路径差异与完成状态 |

A 不能遇到第一次 Rejection 就停；否则无法识别其下方的 PASS island。B 中 linear arm 的候选顺序、
每坐标覆盖范围、何时提交、终止及重试规则需预先冻结。若 B 使用遇到首个 Rejection 即停的局部下降，
它只属于整轮策略对照，不能充当全序列真值采集。

B 的后续 Slice 会随 current 分叉，不能把两条轨迹拼成单轴序列，也不能把最终向量差异仅归因于二分。
A 的采集成本单列，不冒充生产算法所需调用；离线回放不证明实际墙钟或产品输出资格。

## 3. 观察身份与失败处理

每条观察关联项目内容快照、Cell、精确直接依赖向量、解析/安装策略、实际解析 lock/artifact 身份、
验证命令与执行策略、工具/平台身份及证据来源。固定其他直接坐标不要求传递依赖完全相同，但须按冻结
规则解析并保存实际环境；否则结果无法区分候选变化和环境漂移。

保存 Probe Rejection 的合格归因、操作阶段、执行终态和原始日志；自由文本诊断只能作研究分类，
不得越过 [D005](../designs/D005-pf-failure-and-diagnose.md) 的结果资格。
INDETERMINATE、缺失、超时、预算中断及同点相反直接结果分别报告，不编码为普通 Rejection，
也不通过多数投票生成虚假稳定真值。遇到这类情况保留前缀并停止该评价单元的真值/算法结论；调查或重启
使用独立记录，不覆盖原观察。若继续其他独立 Slice，明确其不消费该不确定结果。

仅在评价域具有完整稳定 P/R 时计算完整序列指标；部分覆盖报告分母、覆盖位置和未完成原因，不能纳入
“未发现 hole 即单调”的计数。项目故障或预算删失不得静默从成功率分母移除。

## 4. 预注册指标

C004 §6.3 拥有研究指标的详细数学口径；执行前冻结权重和阈值，本协议采用以下分组：

- **序列结构：** 完整 Slice 数、候选数、单调比例、P/R 变点与连续区间长度；hole 定义为两侧均有 P
  的连续 R 区间，另报所有较低 P/较高 R 反例。按项目与分辨率分层，已知异常样本单列。
- **点与声明质量：** 最低已观察 P、exact current、floor regret；有输出时分别评价 `A_search` 与
  `A_decl` 的 unsafe admitted coverage 和 PASS coverage。未输出、未实现投影、空间外 current、
  无候选 P、冲突及 incomplete 均按 C004 的边界口径处理，不以零错误冒充有效结果。
- **执行成本：** 逻辑请求、唯一精确向量、实际 oracle 执行（含复验/I）、缓存命中；resolve/install/test
  分阶段耗时、整轮墙钟和资源限制。未执行与耗时未知分开，未知不能填零。
- **算法比较：** 同一 A 单元内正常搜索/linear 的查询与实际执行比值；B 分别报告总成本、最终向量、
  sweep、停止原因和 PASS 资格。分母为零时比值不适用，保留原始计数；不将向量强行排成单一 floor。

如拟合概率模型，训练与留出按项目/依赖分组，固定划分后再评估；离线完整表对策略只通过请求点提供
答案，禁止借用未查询点作指导。C004 的保留普通搜索参考轨迹方案作为明确实验 arm，与现行产品区分。

## 5. 缓存和成本对照

| 模式 | 控制方式 | 解释范围 |
| --- | --- | --- |
| 独立冷缓存 | 各 arm 使用隔离缓存，冻结预置内容与执行顺序/重复方案 | 初次执行成本；不能笼统假定宿主或网络也完全冷 |
| 独立暖缓存 | 从相同冻结种子分别复制，每个 arm 独立写入 | 相同历史起点下的增量成本 |
| 共享证据回放 | 固定 Store 内容与准入规则，单列命中、拒绝和真实复验 | 历史证据复用的潜在收益，不能宣称当前产品已有跨 Run Store |

还需分别记录下载/build/environment/static 等缓存状态；一个 arm 的新结果不得隐式预热另一个 arm。
若研究有意顺序共享，单列实验并冻结顺序，不混入独立算法比值。C008 未形成产品准入时，共享模式限于
明确标记的实验回放。阶段耗时求和不能替代并发/缓存条件下实测整轮墙钟。
