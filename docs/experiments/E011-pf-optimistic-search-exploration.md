## 1. 结论

**有限探索值得进入下一版 Design 的讨论，但本实验不支持直接确定默认参数，也不支持“探索一定比普通二分更好”。**

普通二分在本实验的所有自生成轨迹上都没有发现非单调反例。剪枝前探一个中点确实能打开这个盲区：主矩阵中发现了 14.71% 的单 hole 和 22.40% 的单 PASS island。相同实际探索次数的均匀对照分别为 8.64% 和 9.75%；但剪枝策略也付出了更多细化调用。单点 hole 的发现率仅 1.89%，不能把一次未命中解释为该区间没有 hole。

代价不止可选探索本身。单调输入中剪枝策略没有细化费用，但 N=1024 时平均调用从 10.99 增至 16.98；发现反例后还要支付不受探索预算 B 限制的必要细化费用。

此外，本原型在第一次发现反例时结束原机械搜索，改用反例边界细化。在随机序列中有 31 例、多个翻转区间中有 6 例，最终找到的最小直接 PASS 比普通二分更高。它尊重了已观察证据，却没有保留普通二分原本会发现的全部 PASS。这是下一版 Design 必须处理的搜索目标问题。

## 2. 实验边界与成本口径

输入为固定一维 Slice 的完整 P/R 真值表，版本按候选序号排序。oracle 是查表；搜索只能读取自己发出的 probe，完整真值只用于事后评分。一次新候选查表记为一次 oracle 调用；重复证据读取不收费。

启动前 baseline S 已知为 P，作为沉没成本不计入。两种空间分别覆盖 S 是最高合法候选、S 在候选空间外作为虚拟右锚点。虚拟锚点不执行、不算候选，也不能充当最终 floor。后者允许整个候选空间为 R，结果为没有候选 PASS。

费用分为 `main`（机械搜索）、`explore`（可选探索）、`refine`（证据边界细化）；总成本为三者之和。单 Slice 缓存使每个合法候选最多执行一次，因此本模型总调用最多为 N（内部 baseline 时 N−1）。这不是墙钟模型，不包含安装、resolver、测试命令、并行效率或缓存命中的真实耗时。

本轮没有往 PF 生产代码加入非单调探索，也没有以真实依赖测试作为实验数据。现行搜索对照只通过合成 evaluator 调用公开 `CoordinateSearch.minimize()`。报告不测 speculative 并行、joint 验证、多坐标调度或 marker 投影；搜索不受声明表达能力约束。

## 3. 被比较的算法

| 策略 | 主搜索与探索 | 预算 |
| --- | --- | --- |
| `plain` | 现行机械搜索模型，不主动探索裁剪区间 | 0 次可选探索 |
| `prune` | 普通剪枝前，对足够大的待丢弃区间探一个中点；首次反例后转入共同细化 | 每 Slice 最多 B 次可选探索，可能花不完 |
| `uniform_cap` | 先完成 plain，在剩余未知候选上均匀选一批点，执行整批后细化 | 最多 B 次，未知点足够时花满 |
| `uniform_matched` | 同上，但批量大小取该例 prune 实际花掉的探索次数 | 逐例探索次数与 prune 相等；离线诊断对照 |

这组比较同时改变了**选点位置、探索时机和首次反例后的调度**，不能单独证明中点位置更优。`uniform_matched` 事后知道 prune 花了几次，并非可直接部署的独立策略。相同探索次数也不代表相同总调用次数，细化费用必须另算。均匀网格随预算重排，不是嵌套采样；增加预算不保证每一例保留此前命中的点。

### 3.1 主搜索及探索触发

1. 验最左候选。若 P，已有最小 floor，但右侧仍属于本次可审计的 P 区间。
2. 若最左为 R，在 R/P 锚点之间搜索。主矩阵用机械中点；进入机械搜索时窗口不超过 8，沿用现行逐个向右探测的分支。
3. 新 probe 为 P，审计将被裁剪的右侧 P 区间；为 R，审计将被裁剪的左侧 R 区间。
4. 先检查该区间已有的相反证据。已有反例不能被阈值或预算跳过。
5. 只有区间内部**尚未观察的合法候选数严格大于 T**，且 B 未用完，才取未知候选的较低中位点探一次。这就是本轮离散候选上的 clamped 中点；不探端点、已知点或虚拟锚点。
6. 结果与区间假设一致，继续普通搜索，不递归审计刚产生的两个同色子区间。相反则保留所有事实，转入细化；本原型此后不再主动探索新同色区间。

主配置为 T=8、B=ceil(log2(N+1))。预算属于同一 Slice 的 Search 实例，不在细分区间时重置。没有反例时，探索机会随普通二分剪枝次数增长；不递归审计同色子区间是避免变成全空间扫描的关键。

### 3.2 反例邻域顺序与停止条件

四种策略共用以下细化代码；plain 的正常自生成轨迹已经闭合，不会多花细化调用。

1. 对插入在同色已知端点之间的相反新证据，按发现顺序先探左邻候选、再探右邻候选；已知或越界点跳过。
2. 按坐标从左到右，找到第一对相邻的已知事实：颜色相反，且中间仍有未知候选。
3. 从离反例点最近的端点向另一端探测；距离相同取左端。没有这类反例点时从 R 端出发。距离依次为 1、2、4、8……，限制在另一已知端点内。
4. 遇到异色结果后，在最后同色点与该点间二分，直到两者是候选邻居。
5. 重新扫描所有已知事实，直到每对异色相邻事实之间都没有未知候选。此时最小直接 P 为 floor，其前驱若存在则已有直接 R。**同色端点之间仍可有未发现的 hole/island。**

本原型用这一步闭合全部已知异色边界，没有再启动一轮机械搜索。因此它验证的是上述特定调度，而非所有可能的“细化后恢复搜索”方案。

B 只限制第 3.1 节的可选探索；已发现反例的细化不能因 B 用完而忽略。单独的总调用上限可以中断细化，但此时结果为 `INCOMPLETE`。遇到 I 立即 `INDETERMINATE`；同候选 P/R 冲突立即 `NONDETERMINISTIC`，不覆盖原事实。

## 4. 输入矩阵与指标

| 主矩阵族 | 案例数 | 构造 |
| --- | ---: | --- |
| 单调 | 2,724 | N=16/64/256/1024，枚举全部 floor；两种 baseline 位置 |
| 单 hole | 6,390 | N=16/64/256，原 floor 为 0、N/4、N/2；在 P 尾部插入连续 R |
| 单 PASS island | 5,517 | 同上三个 N，原 floor 为 N/4、N/2、3N/4；虚拟锚点另含 N，在 R 前缀插入连续 P |
| 多个翻转区间 | 384 | 单调表上依次翻转四个随机短区间，可重叠 |
| 随机 | 576 | P 概率为 0.1/0.5/0.9 的独立抽样表；内部 baseline 强制为 P |
| 交替 | 12 | 三种 N、两种起始颜色、两种 baseline 位置 |

hole/island 宽度取去重后的 `{1, 2, 4, N/16, N/4}`，枚举每个合法起点；hole 左侧保留 P，island 右侧保留 R。随机种子固定为 57361。另在 N=64 的 1,994 个单调/hole/island 案例上做九组 T/B 和两组 hint 消融。

主矩阵 15,603 个案例 × 四种策略 = 62,412 行；加上敏感性实验共 150,148 行。另做 N=1…10 全部二值表穷举检查，共 12,276 次策略运行。

发现反例指观察到同 Slice 中较低 P 与较高 R，发现率分母为真值确实非单调的案例数。随机族分母为 545，多区间族为 381，其余非单调族等于案例数。单调族不定义发现率。

floor 精确率按完整真值最左 P 计算。改善/退化均相对同例 plain 的 floor；没有候选 P 按高于所有候选处理。`false_pass` 是乐观推断为 P、实际为 R 的候选个数；`missed_pass` 反之。二者都是**真值表上的诊断指标，不是投影结果或产品正确性声明**。

以下百分比是枚举矩阵上的频率，不能解释为真实版本发生 hole 的概率；全枚举使大 N 和可放置位置较多的族权重更高。

prune 比 matched 多发现单 hole/island，但不存在逐例支配：单 hole 中 prune 独有发现 633 例、matched 独有 245 例；单 island 分别为 1,025 和 327 例。交替序列中 matched 的发现率反而更高。

调用拆分也说明提升并非免费。单 hole 族 prune 共用 61,236 次调用，其中主搜索 28,456、探索 13,940、细化 18,840；matched 同样探索 13,940 次，总调用 54,293，其中细化 7,643 次。剪枝中提前发现反例减少了原主路径调用，但增加了边界处理。

宽度为 1/2/4 时，prune 在单 hole 族的发现率分别只有 1.89%/3.82%/7.83%；在单 island 族为 3.93%/7.07%/13.65%。宽度 64 时为 54.38%/78.12%，但宽度 64 仅出现在 N=256，不能跨宽度汇总推断独立因果。逐例 CSV 保存 N、宽度、位置，可继续做固定 N 的位置分析。

单 hole 族中最左为 P 的 2,922 例尤其关键：plain 只调用一次；prune 每例只花一次探索，即使 B 更大也不会继续拆同色区间。发现率 8.01%，平均总调用 3.31。matched 在这一分层与 prune 完全相同；花更多探索的 uniform_cap 发现率为 35.56%，平均调用 13.66。这说明最左 PASS 分支的发现能力主要受“一次中点后停止”限制。

### 5.3 下界改善与退化

| 输入族 | prune 下界改善 | 下界退化 | 不变 | 误允许 R 个数增加的案例 |
| --- | ---: | ---: | ---: | ---: |
| 单 hole | 256 | 0 | 6134 | 0 |
| 单 island | 676 | 0 | 4841 | 0 |
| 多个翻转区间 | 36 | 6 | 342 | 8 |
| 随机 | 50 | 31 | 495 | 25 |
| 交替 | 0 | 0 | 12 | 0 |

代表负例 `random/64/0/0.1/8`，候选编号从 0 开始，63 是已知 P 的内部 baseline：

```text
plain 主路径：0R → 31R → 47P → 39R → 43P → 41R → 42R
结果：floor=43，共 7 次。

prune：0R → 31R → 探索15R → 47P → 探索55R
55R 与 47P/63P 构成反例，立即切换细化：
54R → 56R → 46R → 53P → 57R → 58R → 60R → 61R → 62P
结果：floor=47，共 14 次，其中探索2、细化9。
```

prune 保存了所有自身观察，但没有去探普通二分后续的 43。46R 与 47P 已相邻，左侧又没有已知 P，所以同色 R 区间内的 43P 仍被遗漏。完整真值的最左 P 实际在 16；两个策略都没找全。

同例 matched 用 14 次保留 floor=43，uniform_cap 用 23 次找到 37。这不证明均匀采样总体更优，而是说明“保留已见事实”不等于“保留另一条未执行轨迹的搜索收益”。uniform 两策略先走完 plain，所以最小直接 P 不会上升；它们仍有误允许 R 数增加的案例，不能宣称所有质量指标均不劣。

## 6. 阈值、预算和 hint 消融

N=64 固定案例集；下表只列 prune。hole/island 格为“发现率 / 平均总调用”。

| T | B | 单调平均调用 | hole | island |
| --- | --- | ---: | ---: | ---: |
| 4 | 0 | 6.90 | 0.00% / 4.23 | 0.00% / 6.82 |
| 4 | 1 | 7.90 | 13.77% / 6.65 | 17.61% / 9.94 |
| 4 | 7 | 9.87 | 19.46% / 7.88 | 30.82% / 12.37 |
| 16 | 1 | 7.90 | 13.77% / 6.65 | 17.61% / 9.94 |
| 16 | 7 | 7.90 | 13.77% / 6.65 | 17.61% / 9.94 |
| 64 | 7 | 6.90 | 0.00% / 4.23 | 0.00% / 6.82 |

T=16 时 B 从 1 加至 7 没有效果，因为这组路径只触发一次足够大的裁剪；T=64 完全不触发探索。T=4、B=7 有更高发现率，也增加了单调输入成本。因此 B 是上限，T 和路径共同决定实际花费；不能只比较配置预算。

hint 消融只把第一枚中间 probe 改为候选范围约 1/4 或 3/4 处，再恢复机械搜索；hint 不读取 oracle 真值。1/4 时单 hole/island 分别发现 122/213 例，平均调用 6.57/12.65；3/4 时为 163/198 例、8.07/12.05。探测顺序会改变收益，但这不是 ty 静态分析或真实 guided 搜索的效果测量。

## 8. 下一版 Design 应回答的问题

实验支持明确的有限探索机制和事实优先细化；以下选择尚不能由本轮数据替产品决定：

1. **搜索目标：** 是否接受提前细化偶尔使 floor 比原二分更高？若不接受，应单独比较保留原机械路径、延后细化或恢复未完成搜索的方案。保留更低直接 P 也不等于保证完整允许集合更优。
2. **费用承诺：** B 只管可选探索；发现反例后的必要细化和整 Slice 总上限如何协调、何时报告 incomplete，需要独立规则。本矩阵最大细化成本不是任意复杂序列的上界承诺。
3. **覆盖目标：** 最左 P 分支仅探一个中点能否接受？若要求更高发现率，就要为多点或递归分配额外预算。T=8/B=ceil(log2(N+1)) 是实验参数，尚无默认值依据。
4. **证据与投影：** 同色未知区间继续是乐观推断，已见 R 必须保留为事实；搜索结果应独立于声明投影，再按现有依赖声明及 marker 语义表达其最大可表示子集。此处未测编码、裁剪或 apply。

本轮不估计真实 hole 分布，不给出“漏掉 hole 的概率低于某值”的保证，不以合成 oracle 调用数换算真实运行时间。下一步可据此写 Design 草案；本报告不代表 C004 已转为接受的设计或 PF 已支持该特性。
