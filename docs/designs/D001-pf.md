## 1. 结果承诺

PF 的搜索单位是一个可独立安装的分发包和一个 compatibility Cell：

```text
(精确 uv target triple, CPython minor, extra surface)
```

Workspace 只提供发现、配置、source 与测试支撑；每个可安装成员独立搜索并拥有自己的 `package-floor.json`。Root 仅在自身可安装时成为 package。

在报告固定的源码快照、Cell、source、候选与验证策略下，PF 返回一个直接完整验证的坐标最小向量：固定其他受管直接依赖后，没有一个坐标还能降低到冻结候选中的更早样本并通过。

该结果不是直接依赖笛卡尔积的全局最小值，也不证明未探测版本、其他组合或报告范围外环境兼容。v1 假设每个一维 Slice 为 `REJECTED* PASS*`；发现反例时以 `NON_MONOTONIC` 停止并禁止 apply。PF 只发现下界，不搜索或生成不兼容上界；已有上界、排除项与 marker 保留。

## 2. 项目与依赖范围

PF 支持静态 `project.dependencies` 与 `project.optional-dependencies`；相关字段由 `project.dynamic` 提供时保守失败。声明保留稳定 ID、base/optional 位置、extra、规范化名称、requested extras、specifier、marker、source、原文和项目相对路径。

同一位置中同名声明在任一活跃 Cell 上不得重叠；base 与 optional group 的同名约束在共同活跃时取交集。`check` 可验证任意合法 PEP 508 marker；参与 search/apply 的受管声明只允许 `python_version`、`sys_platform` 与 `platform_machine` 投影，使用其他 marker 维度的声明必须设为非受管。

`managed-deps` 与 `unmanaged-deps` 互斥：

```text
managed-deps 存在     managed = 可搜索直接依赖 ∩ managed-deps
unmanaged-deps 存在   managed = 可搜索直接依赖 − unmanaged-deps
均不存在              managed = 所有可搜索直接依赖
```

`managed-deps = []` 表示不移动依赖。显式把固定依赖列为 managed 是配置错误。没有下界或带 `>`/`>=` 下界的 direct registry dependency 可搜索；已有下界不限制向下探索，`<`、`<=` 与 `!=` 始终过滤候选并在 apply 时保留。`==`、`===`、`~=`、direct URL、Git、path 和 workspace source 是 fixed，只参与解析与验证。

候选发现与安装消费同一 SourcePlan。v1 支持：

- 唯一明确的 default/named registry index；
- 源快照内的 path/workspace fixed dependency；
- 精确 Git commit；
- HTTPS 且带单一 SHA-256 的 PEP 508 URL，或带完整性信息的 uv URL source。

可变 Git ref、无完整性 URL、歧义 index、越过 root 的路径、带凭据或非 HTTPS 的 PEP 508 URL 均失败。公共 identity、报告、日志和终端不得保存凭据。Source 或 artifact identity 变化使旧证据失效。

## 3. Compatibility matrix

矩阵是：

```text
精确 uv target triple × CPython minor × extra surface
```

每个进程只执行与宿主精确匹配的 target；其他 host 的覆盖必须由 `pf merge` 补齐。

`python` 使用如 `3.11` 的 CPython minor。省略时依据 `requires-python` 与本机可用的默认稳定 CPython 推断。Proposal 记录实际 patch、implementation 与 ABI；v1 不支持 PyPy、free-threaded 或 debug interpreter。

`platform` 必须是完整 uv target triple；省略时使用宿主 target。Extra surface 规则为：

```text
none -> [[]]
each -> [[], 每个单独 extra]
all  -> [[], 每个单独 extra, 全部 extras]
```

默认 `each`。`extra-surfaces` 是显式形式，必须包含 `[]` 和每个 extra 的单元素面；它与 `extras` 互斥。

## 4. 候选与验证边界

每个 dependency/Cell 第一次查询后冻结规范化、升序、非空的精确候选快照；运行中新发布版本不参与。候选不高于 baseline，排除 yanked，默认排除 prerelease。

`distribution` 为 `wheel | sdist | any`，默认 `wheel`；`any` 优先匹配 wheel。Candidate 始终绑定实际 artifact locator/hash 与精确版本。

`release-granularity` 为 `major | minor | patch`，默认 `minor`；major/minor 系列使用快照内最新合格精确 release 作为代表，apply 不截断版本。`search-space` 支持：

```text
all            × major | minor | patch
current-major  × minor | patch
current-minor  × patch
```

列表形式按 dependency 提供非空 PEP 508 specifier；不得含 extras、marker、URL 或 source，同名重复无效。未列 dependency 使用 `all`。空间可以不含 baseline；空间内无 PASS 时是 `NO_PASS_IN_SEARCH_SPACE`，不能用空间外 baseline 冒充 floor。

一次验证使用包含 tracked、staged、unstaged 和未忽略 untracked 文件的不可变源码快照，并排除 `.git`、虚拟环境、常见缓存、`.pf`、PF 临时目录和 `package-floor.json`。每个 Proposal 使用独立可写副本和虚拟环境；PF 不使用 Git worktree、操作者 `.venv`、`uv sync` 或 `uv run`。

完整验证要求 `[tool.pf].test-command` 和默认名为 `test` 的 dependency group；group 可为空。命令是无 shell argv，不能以 `uv run` 开头。Harness 的原始/relaxed 适用规则、两次 resolution/一次 installation 与 resolver negative-evidence 资格只由 D012 定义；D013 的 pytest observer 只提供诊断遥测。

验证统一消费 D005 定义的 `PASS | REJECTED | INDETERMINATE`。Static regression 本身不是 disposition；Probe Indeterminate 不能建立边界并终止当前 Cell；Baseline Rejection/Indeterminate 都因缺少 PASS anchor 终止。相同 Proposal 与 Evaluation context 的完整测试一次运行内最多执行一次；PF 不自动重试 flaky tests，冲突结果为 `NONDETERMINISTIC`。

## 5. 命令

```text
pf smoke [package] [--jobs auto|N]
pf check [package] [--jobs auto|N]
pf search [package] [--jobs auto|N] [--max-duration DURATION]
pf explain [package]
pf apply [package]
pf minimize [package] [--jobs auto|N] [--max-duration DURATION]
pf diagnose [package] [--failure FAILURE_ID]
pf merge REPORT [REPORT ...] --output PATH
```

`package` 是规范化包名、package 目录或 `pyproject.toml`；省略时选择 root 配置允许的全部可安装 package。`--jobs` 默认 `auto`。`--max-duration` 接受正整数加 `s | m | h`，`none` 表示无限；达到时停止新增调度并保存 incomplete report。

| 命令 | 产品行为 |
| --- | --- |
| `smoke` | 在当前声明允许的尽可能新环境中做 fresh install、static capture 和一次完整测试；不搜索、不读写报告 |
| `check` | 捕获 highest static baseline，再验证声明的 `lowest-direct`；不搜索、不读写报告 |
| `search` | 验证 highest baseline 后执行 D003，更新 package 的报告；绝不编辑项目元数据 |
| `explain` | 离线读取报告，展示 floor、coverage 与 apply blocker |
| `apply` | 只从 complete/current report 编辑元数据；不解析环境、不运行 `ty` 或测试 |
| `minimize` | 顺序复用 search；仅全部报告 complete 且 search 成功时复用 apply |
| `diagnose` | 离线读取报告与 latest Journal 中的 FailureRecord；不重放、不修改 |
| `merge` | 合并 identity 兼容的报告，重算 coverage/projection 后原子写入 output |

各命令的 Attempt 序列、Role、Journal 和终态聚合由 D008 定义；终端输出由 D006 定义。

## 6. 报告与 apply

`package-floor.json` 是 search 输出和 apply/explain/merge 输入，不是跨运行 Evaluation cache。`search` 可写 incomplete report；只有 complete、未漂移且可表示的报告能 apply。Schema 1 wire、typed refs、identity 复算、64 MiB 读取上限、规范编码和原子持久化只由 D014 定义。公共报告不保存 process output、run ID 或本地日志路径。

同 generation 更新保留未在本机执行的 host Cells，并替换本次 Cells；source、policy 或 declaration identity 变化开始新 generation。Merge 要求 generator、package、source、policy、declarations 与 target Cells 兼容；相同 Cell 的重复结果必须完全一致，不能按时间戳选胜者。

Apply 要求：

- Schema、package、source snapshot、policy 与 report identity 有效且当前；
- 所有 target Cells 成功并完整覆盖；
- 每个 floor 都由对应 final PASS Proposal 直接授权；
- 全部 projection 能用 v1 支持的 marker 精确表达。

Projection 从 `Cell -> ExactFloor` 分组生成 PEP 508 requirements，再在全部 target Cells 上重求值；漏选、多选或同 Cell 命中不同 floor 都不可表示。相同 `sys_platform/platform_machine` 的 GNU/musl target 若 floor 不同，v1 无法区分，必须拒绝。Extra 通过 optional group 与 Cell activation 表达，不生成 `extra == ...` floor marker。

写回值是验证过的精确 `>=version`；已有上界、排除项、marker、source、位置、注释和无关字段保留。批量编辑使用恢复日志、原子替换与回滚，重复 apply 幂等。

## 7. 配置

PF 依次合并 root `[tool.pf]`、root `[tool.pf.package.<name>]` 与成员 `[tool.pf]`；后者优先，列表替换而非拼接。Root-only `packages`/`exclude-packages` 控制 discovery，package override 的 `path` 指定成员路径。

现行省略默认值：

```toml
[tool.pf]
extras = "each"
release-granularity = "minor"
search-space = "all"
distribution = "wheel"
allow-prereleases = false
ty-args = []
test-group = "test"
command-cwd = "package"
jobs = "auto"
resolve-timeout = "10m"
ty-timeout = "10m"
test-timeout = "30m"
```

`python`、`platform`、`managed-deps`、`unmanaged-deps` 与 `test-command` 没有静态默认值；前两者按 §3 推断，依赖选择省略时管理全部可搜索直接依赖，完整验证缺少 `test-command` 时配置失败。`command-cwd = "root"` 改为快照 root。阶段 timeout 可设 `none`。

Configured verifier 的 terminal 映射只由 D005 定义。该映射不可配置；不存在
failure-exit-code 或 pytest authority profile 选项，D013 observer 只提供 runtime diagnostics。

CLI 选项覆盖对应调度输入。`jobs`、总时限和日志表现不进入 compatibility policy identity；会改变 source、候选、解析、static、failure 或 test 语义的有效配置必须进入对应 identity。

PF 发行依赖精确固定 uv `0.12.5` 与 ty `0.0.74`。Resolver protocol 只接受已资格化 uv `0.12.5`；其他版本 fail closed。升级工具前必须重新资格化并同步依赖与现行契约。

## 8. 退出码

```text
0  成功
1  当前声明、smoke test 或 Baseline Rejection
2  没有可应用的 floor
3  调用、配置、Schema、coverage 或项目漂移错误
4  Baseline/Probe Indeterminate、基础设施错误或 timeout
```

D008 负责命令聚合；本节只把最终结果映射为数值退出码。`diagnose` 成功展示记录时返回 `0`，不继承被诊断运行的退出码。

## 9. v1 非目标

- 传递依赖最小化或直接依赖笛卡尔积搜索；
- 非单调区间细化、version-hole 认证、自动 `!=` 或上界发现；
- 根因归属、partial tests、测试选择或 flaky 自动重试；
- 没有完整 runtime PASS 的 static-only floor；
- `diagnose` 隐式重放或自动修复；
- 跨运行 Proposal/Evaluation environment cache；
- 非宿主 target 执行；
- 无法表示或 incomplete 证据的部分 apply。
