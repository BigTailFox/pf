## 1. 结果承诺

PF 的搜索单位是一个可独立安装的分发包和一个 compatibility Cell：

```text
(精确 uv target triple, CPython minor, extra surface)
```

Workspace 只提供发现、配置、source 与测试支撑。每次 package-scoped invocation 必须选择恰好一个可安装 target；该 target 独立搜索并拥有自己的 `package-floor.json`。省略 selector 时只选择含静态 `[project]` 的可安装 root；non-package root 必须显式使用 `--package` 选择成员。

PF 返回固定 configured validation contract `C` 下经过完整验证的坐标最小向量 `F_C`：固定其他受管直接依赖后，没有一个坐标还能降低到冻结候选中的更早样本并通过。`C` 绑定源码快照/SourcePlan、target、Python、effective extra surface、candidate/artifact policy、normalized external harness、ty、test command 和 environment policy。它不是脱离验证 oracle 的 intrinsic compatibility floor。

该结果不是直接依赖笛卡尔积的全局最小值，也不证明未探测版本、其他组合或报告范围外环境兼容。v1 假设每个一维 Slice 为 `REJECTED* PASS*`；发现反例时以 `NON_MONOTONIC` 停止并禁止 apply。PF 只发现下界，不搜索或生成不兼容上界；已有上界、排除项与 marker 保留。

执行契约采用可靠归因优先、正常非零兜底：有效 resolve/install 请求的未知普通非零（包括其内部
build 失败）拒绝当前 Attempt，不证明 UNSAT、单依赖根因或可重复失败。后端可能将网络/权限/
内部问题包装为普通非零，误拒绝可能抬高下界、遗漏可行向量或导致无结果。PF 不增加重试、quorum
或严格/实用双模式。直接外因、一致性破坏、异常终态和辅助操作失败仍按 D005 为 Indeterminate。
最终精确向量必须实际解析、安装、复证图并取得完整 configured verifier PASS；同 context 的既有
直接完整 PASS 可复用，static-only 和 failed-set PASS 不足以作为 final。

Baseline、declaration 与 probe 对这些结果的处理由 [D008 §3](D008-pf-verification-run.md#3-命令序列) 定义。

## 2. 项目与依赖范围

PF 支持 target 的静态 `project.dependencies` 与 `project.optional-dependencies`；相关字段由 `project.dynamic` 提供时保守失败。Workspace membership 与 member 自身依赖不建立 target coordinate。声明保留稳定 ID、base/optional 位置、extra、规范化名称、requested extras、specifier、marker、原文和项目相对路径；source 由同名 `DependencySourceRoute` 独立拥有。

同一位置中同名声明在任一活跃 Cell 上不得重叠；base 与 optional group 的同名约束在共同活跃时取交集。
所有命令的受管声明使用 portable Cell marker profile，精确支持 `python_version`、`sys_platform`、
`platform_machine`、`platform_system`、`os_name`。全部合法声明完整记录原文、marker identity 与定位；
受管声明整条表达式在建 Cell 前检查资格，即使 optional 未启用、逻辑分支不可达或没有活跃 Cell。
其他字段拒绝准入，不删除条件、部分投影或静默降为非受管；用户可显式设置非受管。

`python_version` 等于 Cell minor；四个平台字段只由 exact target 得出，不取 PF host 默认值：

| target family | sys_platform | platform_machine | platform_system | os_name |
| --- | --- | --- | --- | --- |
| `*-unknown-linux-gnu` / `*-unknown-linux-musl` | linux | target architecture | Linux | posix |
| `*-apple-darwin` | darwin | aarch64 → arm64，其余保持 | Darwin | posix |
| `*-pc-windows-msvc` | win32 | x86_64 → AMD64，aarch64 → ARM64，其余保持 | Windows | nt |

未知 target family、非法 marker、unsupported portable 字段或不可求值比较是配置错误、退出 3，早于
snapshot/Attempt/resolution/verifier；错误提供用途和声明定位，不把不可求值当 False。
portable activation 由 optional group 是否在 Cell surface 与整条 marker 求值共同决定，唯一决定 active IDs、
overlap、managed coordinates 和 lower-bound anchor。别名 overlap 仍按完整 Cell matrix 实际求值判断。

fixed/unmanaged 维持既有准入与原样写回，无 floor 修改，但参与 activation、overlap 与整组投影/授权
检查。其 contextual 求值显式覆盖上述五字段，其他字段沿用现行 context/host default；`extra` 对空 extra
与 Cell surface 逐项求值取 any。混合表达式不取得跨宿主或 patch 可移植承诺；不能在 portable 失败后
重试 contextual 路径。五字段之外（含可推导的 CPython implementation name）及精确 patch planning
留待后续；本次不增加 Cell axis，也不声称某 patch PASS 验证了全部 minor patches。

`managed-deps` 与 `unmanaged-deps` 互斥：

```text
managed-deps 存在     managed = 可搜索直接依赖 ∩ managed-deps
unmanaged-deps 存在   managed = 可搜索直接依赖 − unmanaged-deps
均不存在              managed = 所有可搜索直接依赖
```

`managed-deps = []` 表示不移动依赖。显式把固定依赖列为 managed 是配置错误。没有下界或带 `>`/`>=` 下界的 direct registry dependency 可搜索；target direct dependency 若由唯一 workspace member 提供、忽略 development override 后恰有一个安全 registry route，也使用相同 managed/unmanaged 规则。已有下界不限制向下探索，`<`、`<=` 与 `!=` 始终过滤候选并在 apply 时保留。`==`、`===`、`~=`、direct URL、Git、path，以及 fixed/unmanaged workspace source 只参与解析与验证。

每次 `smoke` / `check` / `search` invocation 从选中 target 只形成一个 canonical `SourcePlan`，绑定逐 dependency 的 development/search route 与 `DEVELOPMENT | SEARCH` mode。`smoke` 使用 development route；`check`/`search` 使用 search route；Runner 把该计划注入全部 Cell operation，候选查询、harness、project/optional environment resolution、artifact 复证、Attempt 与 report identity 必须闭合到同一计划及其唯一 identity。v1 支持：

- 唯一明确的 default/named registry index；
- 源快照内的 path/workspace fixed dependency，以及受管 workspace direct dependency 的安全 registry search route；
- 精确 Git commit；
- HTTPS 且带单一 SHA-256 的 PEP 508 URL，或带完整性信息的 uv URL source。

可变 Git ref、无完整性 URL、歧义 index、越过 root 的路径，以及带凭据、query 或非 HTTPS 的 registry/PEP 508 URL 均失败。公共 identity、报告、日志和终端不得保存凭据。Source route、mode 或 artifact identity 变化使旧证据失效。

## 3. Compatibility matrix

矩阵是：

```text
精确 uv target triple × CPython minor × extra surface
```

每个进程只执行与宿主精确匹配的 target；其他 host 的覆盖必须由 `pf merge` 补齐。本宿主有 Cell、全部为 `CellSuccess`、且 incomplete reasons 仅为其他宿主 `MISSING_CELL` 时，`search` 退出 `0` 并写出 incomplete report，供后续收集与 merge；本宿主无匹配 Cell、同宿主仍有缺失 Cell、或本机失败与远端 missing 混合时，不得使用该退出。

`pythons` 使用如 `3.11` 的 CPython minor，必须非空、排序唯一，且只能缩小 `project.requires-python`；省略时依据 `requires-python` 与本机可用的默认稳定 CPython 推断。Proposal 记录实际 patch、implementation 与 ABI；v1 不支持 PyPy、free-threaded 或 debug interpreter。

`platforms` 必须是非空、排序唯一的完整 uv target triple；省略时使用宿主 target。

有效 test group 中 canonical distribution name 等于当前 target 的 requirement 是 project-surface
requirement；裸自引用消去，带 extras 的活跃自引用取 union，形成每个 `(target, Python)` 的 required base
`R`。PF 始终安装 target，自引用不成为 external harness 或额外 source route。

Requested extras 按 packaging extra-name 规则匹配 target 静态 optional-dependency 声明名；未知或规范化
重名失败。自引用 marker 使用 §2 相同五字段 portable profile 与整条表达式预资格，值来自 planned Python
minor 与 exact target；其他变量 fail closed，不读取 host 值猜测。无 specifier 的 dynamic version 合法；
活跃 specifier 必须由静态 `project.version` 满足，dynamic version 或不满足时配置失败。URL/Git/path
自引用不能替换当前 target source。原文和 root/member/include provenance 用于 planning 错误定位。

令 `E` 为声明 extras，`N` 为其中 dependency array 非空的组；policy 只探索 `selectable = N - R`：

```text
none -> {empty}
each -> {empty} union {每个 selectable singleton}
all  -> {empty} union {每个 selectable singleton} union {selectable}
```

默认 `each`；自动展开跳过空 extra group（如 `security = []`），但非空声明中的 marker 不活跃不算空组。
显式 custom surface 和自引用 required extras 可以保留已声明的空组。每个 policy surface 和已资格化为 `E` 子集的 custom `extra-surfaces` 均先与 `R` union，
再按长度和名称排序去重；`none` 表示不主动探索 required base 之外的 extras。`Cell.extra_surface` 是唯一
实际安装 surface，active declarations 从它重算，candidate/search/floor/apply 因此看到 required extra
依赖。自引用不引入 hidden surface、额外配置项或 report 字段。

## 4. 候选与验证边界

候选观测/准入、系列 DSL、条件默认、采样与 baseline artifact 选择域只见
[D037](D037-pf-candidate-search-policy.md)。本节保留统一验证边界；原 §4 的候选规则已完整迁移，
旧章节地址继续用于导航。

`resolve-artifact` 为 `wheel | sdist | any`，默认 `any`，统一约束 smoke/check/search 的 project/environment registry resolution 与 Candidate artifact；不一致不得形成 PASS。

一次验证使用包含 tracked、staged、unstaged 和未忽略 untracked 文件的不可变源码快照，并排除 `.git`、虚拟环境、常见缓存、`.pf`、PF 临时目录、`package-floor.json` 和 `uv.lock`。`uv.lock` 既不进入快照 identity，也不物化到 Proposal 副本；PF 的解析只使用当前项目声明与自身 ResolutionPlan。每个 Proposal 使用独立可写副本和虚拟环境；PF 不使用 Git worktree、操作者 `.venv`、`uv sync` 或 `uv run`。

SourceSnapshot 路径成员规则不因 apply 改变。`ProjectPlan`拥有的root、workspace与递归in-tree path package `pyproject.toml`使用`PyprojectIdentity(path, mode, remainder_digest, dependency_arrays_digest)`：PEP 621 dependencies/optional-dependencies单独计算dependency arrays identity，其余parsed TOML计算remainder identity；普通路径仍使用blob identity。完整snapshot digest同时绑定普通entries与全部owned pyproject identities，具体wire与摘要前缀由D014定义。

完整验证的 dependency group 可省略；按 §7 的显式或 dev/test/空选择语义归一化。省略 `test-command` 时为 `["pytest"]`，显式 command 整体替换；命令是非空无 shell argv，不能以 `uv run` 开头。不自动发现 pytest/tox/nox，也不为缺失命令 fallback。Harness 的原始/relaxed 适用规则、project/optional environment resolution 与一次 installation 与 resolver negative-evidence 资格只由 D012 定义；D013 的 pytest observer 只提供诊断遥测。

PF 只支持满足下列用户测试 oracle 契约的 `test-command`：对同一 Proposal，测试不得留下会被后续 pytest invocation 观察到的外部副作用；用例之间不得通过执行顺序、fixture 生命周期或共享可变状态形成关联副作用。单独运行一个已收集的失败 nodeid 必须是可靠的负向 oracle。PF 不隔离外部数据库、队列、服务或用户共享缓存，也不提供 pruning opt-out。

direct pytest（`pytest` / `py.test` / `python -m pytest` 及其 `python3` / `pythonX.Y` 变体）**原样保留每个用户 argv token**，并在第一个字面 `--` 之前（无 `--` 时在末尾）追加 PF-owned `--maxfail=1` 与 `-o cache_dir=<invocation-temp>`。该 overlay 覆盖用户 CLI、ini `addopts` 与 `PYTEST_ADDOPTS` 的合法早期值，**不删除**用户的 `-x` / `--exitfirst` / `--maxfail` / `-o cache_dir`。overlay 适用于 smoke、check、baseline 与 search。generic command 的 argv 完全不变。

搜索期对带 active dependency 的 oracle-probe，PF 可以用已知失败 nodeid 做拒绝预言，并在首败后提前结束；不做任意用户选测、不用子集冒充 PASS、不重试 flaky。PASS 只来自不收窄用户 collection 的原命令阶段 `NormalExit(0)`。ty 诊断或不可用不单独形成兼容性拒绝。

验证统一消费 D005 定义的 `PASS | REJECTED | INDETERMINATE`。Static regression 本身不是 disposition；Probe Indeterminate 不能建立边界并终止当前 Cell；Baseline Rejection/Indeterminate 都因缺少 PASS anchor 终止。相同 Proposal 与 Evaluation context 的完整测试一次运行内最多执行一次；PF 不自动重试 flaky tests，冲突结果为 `NONDETERMINISTIC`。

## 5. 命令

产品周期：

```text
接入     pf smoke → pf search → pf explain → pf apply
稳态     pf check（可加入 CI）
重定界   作者主动治理，或 check 失败后选择 pf search → pf apply
```

`check` 只消费当前 package 声明与配置，不要求报告、Git 仓库或曾执行 search/apply。每次 invocation 都重新准备环境；declaration prepare 成功后运行原 configured verifier 的完整命令阶段。历史 PASS、REJECTED 或相同 snapshot 均不跳过本次验证。`check` 继续使用现行 `lowest-direct` 语义；不从旧报告恢复精确向量。用户自行提交、回滚或修改文件；Git dirty 与内容 drift 是不同事实。

```text
pf smoke [--package PACKAGE] [--max-cells auto|N] [--test-jobs auto|N]
pf check [--package PACKAGE] [--max-cells auto|N] [--test-jobs auto|N]
pf search [--package PACKAGE] [--max-cells auto|N] [--ty-jobs auto|N] [--test-jobs auto|N] [--max-duration DURATION] [--search-resolution major|minor|patch]
pf explain [--package PACKAGE]
pf apply [--package PACKAGE] [--search-resolution major|minor|patch] [--force]
pf minimize [--package PACKAGE] [--max-cells auto|N] [--ty-jobs auto|N] [--test-jobs auto|N] [--max-duration DURATION] [--search-resolution major|minor|patch]
pf diagnose FAILURE_ID [--package PACKAGE]
pf merge REPORT [REPORT ...] --output PATH
```

`diagnose` 的 Failure ID 为必填位置参数；CLI 接受 `failure-<16 hex>` 或短 `<16 hex>`，统一为完整 canonical ID 后交给 workflow。

`--package` 只接受规范化后唯一匹配的 distribution name，不接受路径、glob 或额外 positional；可以显式选择可安装 root。省略时只选择可安装 root，不回退到全部 members。合法形状但未知/重复的名称是配置错误；非 distribution-name 形状是带 Usage 的调用错误。`smoke`/`check` 只有 `max-cells` 与 `test-jobs` 两个 scheduling override；`search`/`minimize` 另有 `--ty-jobs`。省略时继承 effective config，显式 `auto|N` 覆盖。共享 `[tool.pf].ty-jobs` 仍可配置并按既有规则校验，但只影响 Search 的静态工作；Smoke/Check 不因这些设置执行 ty。`--max-duration` 接受正整数加 `s | m | h`，`none` 表示无限；达到时停止新增调度并保存 incomplete report，且只属于 search/minimize。`--search-resolution` 只属于 search/apply/minimize，省略时使用 effective 配置，显式值覆盖全局与逐依赖 resolution；apply 用同一覆盖值复核报告策略，不重新搜索。

| 命令 | 产品行为 |
| --- | --- |
| `smoke` | 对单 target 以 development source 做 fresh install 和一次完整测试；不运行 ty、不搜索、不读写报告 |
| `check` | 对单 target 以 search source 按 D012 决定是否先准备 highest harness baseline，再验证声明的 `lowest-direct`；不运行 ty、不搜索、不读写报告；不要求先前 search/apply |
| `search` | 验证 highest baseline 后执行 D003，更新 package 的报告；绝不编辑项目元数据 |
| `explain` | 离线读取报告，展示 floor、coverage 与 apply blocker |
| `apply` | 从当前声明与报告final roots取得一次workspace授权后编辑元数据；`--force`只waiver source-layer drift；不解析环境、不运行`ty`或测试 |
| `minimize` | 顺序复用search与默认apply；MissingSelector可自动scoped，失败或局部Cell仍停止。本宿主全部成功且只缺其他宿主时，search 退出 0，默认 apply 仍按 Authorizer 授权，CLI 必须提示剩余宿主与 `pf merge` |
| `diagnose` | 离线按一个必填 Failure ID 读取选中报告或 latest Journal；只展示该来源内的 Failure 权威；不读 ty-cache、不渲染静态材料；不搜索静态 fact ID、不重放、不修改 |
| `merge` | 合并 identity 兼容的报告，重算 coverage/projection 后原子写入 output |

各命令的 Attempt 序列、Role、Journal 和终态聚合由 D008 定义；终端输出由 D006 定义。

## 6. 报告与 apply

`package-floor.json` 是search输出和apply/explain/merge输入，不是跨运行Evaluation cache，也不是
Run 内 ty-cache。一次`search`只更新所选 target 的一份report；`explain`/`apply`/`diagnose`也只定位该target。`search`可写incomplete report；apply只信任final `CellResult` roots，不把历史候选`REJECTED`当成当前blocker。Schema 1 wire、typed refs、identity复算、64 MiB读取上限、规范编码和原子持久化只由D014定义。公共报告不保存process output、run ID、本地日志路径、原始 TyCheck 或apply-time scope/waiver/history。

报告更新、generation compatibility 与 merge 冲突处理只由 [D014 §5](D014-pf-report-schema.md#5-module-interface) 定义。

Apply 从当前 target 独立形成一个 SEARCH SourcePlan，首先精确比较 report/current plan，再复核 Schema/package、execution/guidance/search 三类 policy、requires-python、当前platform声明、dependency语义和owned pyproject身份。execution-policy-mismatch 与 search-provenance-mismatch 必须可区分；`--force` 不豁免 policy 不匹配。每个EvidencePlatform必须完整覆盖其Python minor × extra surface且全部final roots为`CellSuccess`；没有final success是“无可应用floor”。任何已有root失败或局部缺Cell、`NON_MONOTONIC`、不可表示projection及identity/dependency漂移都阻止default与force。Apply只编辑target requirement arrays并保留`[tool.uv.sources]`与member metadata；受管workspace member的静态version必须经该 plan 的冻结 metadata 满足 intended requirement，动态version因无法离线证明而在编辑前阻止，均不可由`--force`豁免。

Apply scope由当前`EffectiveConfig.target.platforms`与报告证据自动决定。省略`platforms`或显式一个uv triple时，报告target与声明一致后使用`DECLARED_MATRIX`且不生成平台marker。显式多个triples时按PEP 508可表达的`ApplySelector = (sys_platform, platform_machine)`分组：全部selector有完整证据仍是`DECLARED_MATRIX`；完全没有root的MissingSelector触发默认`PLATFORM_SCOPED`，已授权selector写floor，未授权selector保持original有效约束。GNU与musl是同一selector；一个完整libc variant的唯一floor可外推，两个observed variants floor不同则不可表示。某selector内已有但不完整或非成功root始终阻止。

Projection按`DependencyGroupKey = (pyproject_path, location, optional_group, canonical_name)`重生成整组requirements，再在全部report TargetCells上重求值。写回floor是final PASS Proposal授权的精确`>=version`；保留上界、排除项、requested extras、source、位置、原marker语义及fixed/unmanaged声明。PLATFORM_SCOPED补集只对已授权selectors做De Morgan，不按MissingSelector逐条列举，也不使用无marker兜底行。

原 `platform_system` / `os_name` marker 不改写为别名；生成 selector 仍只含 canonical
`python_version/sys_platform/platform_machine`，与原 marker 取 conjunction，不扩大二元 ApplySelector。
在全部 TargetCells（不只是 apply host）上，projected active requirement multiset 必须等于 intended
original/floor multiset。preserved 声明使用 contextual 入口，含纯 preserved group；与冻结 active IDs
不一致同样阻止 apply，不受 force waiver，也不放宽 scoped/libc 缺失或冲突规则。

选中package的current declaration group multiset必须等于report original（WRITABLE）或本次intended projection（NOOP）；数组内无语义重排允许，其它specifier、marker partition、extras、source、fixed/managed ownership或group增删均为不可waiver drift。未选中workspace/path package的dependency-array identity必须精确保持。

`--force`不改变scope、report result或evidence authority，只在上述结构化identity全部通过后waiver普通source path drift，记录`SOURCE_SNAPSHOT_DRIFT`；root/target中uv接收的project-configuration input identity、test-command、requires-python、platform/policy、SourcePlan、选中/未选中dependency drift、workspace member version和不可表示projection均不可waiver。合法apply改变dependency-array identity并开始新snapshot/generation，不与旧generation merge或继承evidence。单target编辑仍使用workspace级冻结授权、事务前snapshot复核、prepared raw bytes compare-and-swap、恢复日志、原子替换与全量回滚；重复apply幂等。

## 7. 配置

PF 只按 root `[tool.pf]` → 选中 member 自己的 `[tool.pf]` 合并；root target 只应用 root layer 一次。scalar 替换，list 与 `dep` AoT 整体替换；member 省略 `dep` 才继承 root 整表，显式 `dep = []` 清空。任何 `[tool.pf.package.*]` 与未知 key 都失败，不保留兼容层。

通用配置的现行省略默认值如下。`search-space`、`search-space-defaults`、`search-resolution`、
`search-prereleases` 和逐依赖策略默认由 [D037 §2–3](D037-pf-candidate-search-policy.md#2-搜索空间与采样) 定义：

```toml
[tool.pf]
extra-policy = "each"
extra-surfaces = []
resolve-artifact = "any"
ty-args = []
# test-group = "test"  # 显式选择；省略按 dev、test、空顺序
test-command = ["pytest"]
test-cwd = "package"
max-cells = "auto"
ty-jobs = "auto"
test-jobs = "auto"
resolve-timeout = "10m"
ty-timeout = "10m"
test-timeout = "30m"
```

`pythons`、`platforms`、`managed-deps` 与 `unmanaged-deps` 没有静态默认值；前两者按 §3 推断，依赖选择省略时管理全部可搜索直接依赖。`managed-deps` 与 `unmanaged-deps` 是互斥 variant，较高 layer 整体替换较低 layer。`test-cwd = "root"` 改为快照 root。三个阶段 timeout 可设 `none`。

`test-group` 与 `test-command` 在 root/member 按普通字段合并。显式 group 必须为非空字符串；该名称在 root/member 任一处存在即选中，缺失时为空且不 fallback。省略时 ProjectLoader 按 `dev`、`test` 顺序查找两处 group keys，空数组也算存在；都不存在时为空。只组合选中名称的 root/member 声明并展开 include-group，不自动 union 不同名称，不读取 uv default-groups。

`TestConfig.group = None` 表示省略意图；`PackagePlan.selected_test_group = None` 表示选择为空。空选择不进入 PF harness parsing/source planning。有效 command 仍在 load 时校验；`smoke`、`check`、`search`/`minimize` 无 group existence gate。默认命令仍为 pytest，不自动安装工具或发现替代命令；按实际 verifier terminal 分类。省略 `pythons` 时允许 planning Python discovery 先运行。

无活跃 external harness 的 Cell 直接安装并复证 project plan 并运行 configured verifier；只有 Search 仍运行 ty。self-reference 只贡献 required extras；无 external requirement 时按 D012 project-only 路径处理。Check 在全部 active harness 均为固定 source 或精确 `==X` / `===X` 时也不走 highest prepare，见 D012。

Configured verifier 的 terminal 映射只由 D005 定义。该映射不可配置；不存在
failure-exit-code 或 pytest authority profile 选项，D013 observer 只提供 runtime diagnostics。

Invocation 开始时只解析一次 `RunLimits(max_cells, ty_jobs, test_jobs, max_duration)`：`auto` max-cells 等于逻辑 CPU 数且至少 1，stage `auto` 继承已解析的 max-cells。max-cells 约束 Cell Scheduler；ty/test limits 是跨全部 Cell 的进程 seam permit pool，不写入外部 argv。Scheduling、总时限与日志不进入三类 policy identity；`resolve-timeout` 与 `test-timeout` 进入 ExecutionPolicy，`ty-timeout` 进入 GuidancePolicy / TyObservationPolicy（[D004](D004-pf-ty-enhancement.md)、[D014 §1.1](D014-pf-report-schema.md#11-identity)）。

PF 发行依赖精确固定 uv `0.12.5` 与 ty `0.0.74`。升级工具前必须重新资格化并同步依赖与现行契约；resolver 的版本/profile 准入由 [D012 §5.1](D012-pf-harness-relaxation.md#51-uv-qualification) 定义。

## 8. 退出码

```text
0  成功。本宿主有 Cell 且全部成功、incomplete reasons 仅为其他宿主 MISSING_CELL 的 search 也返回 0；报告仍 incomplete
1  CLI 调用错误，或当前声明、smoke test、Baseline Rejection
2  SearchSpaceResolutionError、没有可应用的 floor，或非上述 host-partial 的 search incomplete（本宿主无匹配 Cell、同宿主缺失 Cell、本机 no-floor/非单调/不可表示投影；混合 reason 先按 D008 聚合，Baseline Rejection/Indeterminate 不降为退出 2）
3  配置、Schema、apply 授权、coverage 或项目漂移错误
4  Baseline/Probe Indeterminate、基础设施错误或 timeout
130 用户中断（SIGINT / KeyboardInterrupt）。不是基础设施、indeterminate 或搜索结果
```

D008 负责命令聚合；本节只把最终结果映射为数值退出码。`diagnose` 成功展示指定记录时返回 `0`，不继承被诊断运行的退出码；缺失、非法或多余 ID 是退出 `1` 的调用错误，合法但未知的 ID 是退出 `3` 的配置错误。

用户中断不是 CellResult、FailureRecord 或 report reason。解析前、装配中、运行中和未提交持久化阶段退出 `130`，不合成 `package-floor.json`；已提交 artifact 与已落盘 Journal/Process Log 保留。若命令唯一 final 已发出且中断只发生在 close，保留该命令退出码。stderr final 只见 D006；in-flight process-group 停止只见 D007。

## 9. v1 非目标

- 传递依赖最小化或直接依赖笛卡尔积搜索；
- 非单调区间细化、version-hole 认证、自动 `!=` 或上界发现；
- 根因归属或 flaky 自动重试；PF 可以用已知失败 nodeid 做拒绝预言并在首败后提前结束，但不做任意用户选测、不用子集冒充 PASS；
- 没有完整 runtime PASS 的 static-only floor；
- `diagnose` 隐式重放或自动修复；
- 跨运行 Proposal/Evaluation environment cache；
- 非宿主 target 执行；
- 手工选择platform/Cell、对失败或局部Cell证据尽量apply；
- 用force跳过Schema、policy、dependency或projection safety；
- 跨generation merge/rebase evidence或写入apply lineage。
