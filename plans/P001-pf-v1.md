# P001 — PF v1 实施计划与 TDD 记录

- **状态：** 已完成
- **日期：** 2026-08-18
- **契约来源：** [D001](../docs/designs/D001-pf.md)、[D002](../docs/designs/D002-pf-implementation.md)、[D003](../docs/designs/D003-pf-search-algorithm.md)
- **方法：** 纵向 TDD；一个可观察行为对应一次 RED → GREEN，保持 GREEN 后才重构

## 1. 目标与边界

实现 D001 定义的 PF v1，并以 D002 的模块所有权和 D003 的搜索不变量作为完成条件。三份设计文档已经给出公开接口、行为优先级和不支持范围；本计划不扩展 v1，也不把设计中的后续工作提前实现。

完成结果必须能通过安装后的两个等价入口 `pf` 与 `python -m pf`，提供 `check`、`search`、`apply`、`minimize`、`explain`、`merge` 六个命令，并在最小本地项目上完成 `check → search → explain → apply`。

以下环境相关验证与功能实现分开记录：网络 index、非当前 CPython minor、非宿主 target 和多平台 merge 的真实运行，需要对应宿主或外部环境；缺少这些条件不能伪装成通过，但本地 adapter、契约和报告合并行为仍须完整测试。

## 2. 接口与深模块检查

测试只跨越调用方实际使用的接口，不断言私有 helper、内部容器或调用次数。

| 深模块 | 外部接口 | 隐藏的主要行为 | 测试表面 |
| --- | --- | --- | --- |
| `ProjectLoader` | `load(root, package_selection) -> ProjectPlan` | 配置层、workspace/包发现、PEP 508、marker、cell、来源 | 真实临时项目输入与不可变计划 |
| `SnapshotBuilder` | `build(root) -> SourceSnapshot` | Git/非 Git 清单、排除、安全复制、摘要 | 真实临时目录和 materialize 结果 |
| `CandidateBuilder` | `build(package_plan, cell, baseline)` | index/source、构件、版本过滤、粒度、冻结摘要 | fake `UvAdapter` 返回候选，断言快照 |
| `SearchCoordinator` | `search(package_plan, cell, deadline) -> CellResult` | baseline、两阶段搜索、状态机、结果证据 | scripted Evaluator 经完整单-cell 状态机 |
| `CoordinateSearch` | `minimize(...)`（`search.py` 内部 seam） | hint、线性/二分、边界、反例、不动点 | focused 算法测试，并由 coordinator 行为复核 |
| Evaluator | `evaluate(proposal) -> EvaluationEvidence` | 环境、static/full、缓存晋升和状态保真 | fake process adapter 与真实本地子进程 |
| `ReportStore` | `read/write/merge/explain` | Schema 版本、canonical JSON、原子写、merge 一致性 | 真实临时文件和公共报告 Schema |
| `ProjectEditor` | `apply(report, project)` | 授权、round-trip TOML、语义 diff、恢复日志、幂等 | 带注释 fixture 和真实文件 |

明确保留的 seam 只有设计中真实变化的 Evaluator、外部进程和进度消费。文件系统不增加抽象；不创建 `utils.py`、manager/repository 层或裸跨模块 `dict[str, Any]`。

## 3. 行为优先级

### P0 — 证据正确性与保守失败

1. Schema 让非法状态无法构造，公共报告严格、冻结、可规范序列化。
2. compatibility failure 与非证据状态不混淆；后者立即停止 cell。
3. baseline 必须完整通过；搜索维护 D003 的 PASS 当前向量、不下降外坐标、冻结候选和确定顺序。
4. 非单调、非确定、空间内无 PASS、超时、漂移、覆盖缺失或不可表示结果一律禁止 apply。
5. apply 只改变授权的精确 `>=floor`，保留上界、排除项、marker、来源、注释和无关字段。

### P1 — 用户可用主路径

1. 六命令、help、默认值、退出码和 stdout/stderr 分流符合 D001。
2. 静态项目/workspace 发现、配置优先级、依赖分类、matrix 和来源计划正确。
3. `uv pip`、`ty`、完整测试命令均由 adapter 使用显式 argv 和隔离环境运行。
4. search 产出完整或不完整 `package-floor.json`；explain 不执行评估；merge 确定且拒绝冲突。

### P2 — 可靠性与运行体验

1. source snapshot 包含 tracked/修改/未忽略 untracked 文件并排除运行状态。
2. timeout 终止进程组；输出、argv、URL 和环境信息脱敏且有界。
3. 单 cell 串行，多 cell 受全局 jobs 限制；报告顺序不受并发影响。
4. 原子报告/TOML 写入、恢复日志和重复 apply 有验证。

## 4. 纵向切片

每个条目都按“新增一个公开行为测试并确认 RED → 写最小实现并确认 GREEN → 必要重构并保持 GREEN”执行；禁止先批量写完同一切片的所有测试。

### S1 — 可启动的严格 CLI 骨架

- Pydantic 2 依赖、`FrozenSchema`、基础请求/结果与错误类别。
- `pf`/`python -m pf` 同入口，根 help 展示六命令；命令 help 来自 docstring。
- `TerminalPresenter` 独占 Rich，非 TTY 输出稳定，错误映射到 0–4。

### S2 — 工作树到不可变计划

- 三层配置合并、默认值、互斥/未知配置和 root-only 字段。
- 单包与 uv workspace 可安装成员发现；稳定 declaration ID、分类、marker/cell/extras。
- `SourcePlan` 唯一解释来源；`SnapshotBuilder` 安全清单、摘要与 materialize。

### S3 — 当前声明验证

- `SubprocessRunner` 的 argv/cwd/env、signal、timeout、输出上限和脱敏。
- `UvAdapter`、`TyAdapter`、`TestAdapter` 状态分类与命令所有权。
- `EnvironmentFactory` 隔离 proposal、目标图冻结和测试支撑依赖；`FullEvaluator` 支撑 `pf check`。

### S4 — 单 cell floor 搜索

- `CandidateBuilder` 的来源/构件/PEP 440/上界排除/search-space/granularity 快照。
- Static/full cache 分离、一次晋升、冲突检测。
- D003 一维 hint、线性/二分、空空间、非单调和反复 sweep。
- coordinator 的 baseline → static fixpoint → fast path/动态 fixpoint → `CellResult`。

### S5 — 多 cell、报告与查询

- 有界 Scheduler 和规范结果排序。
- `PackageFloorReportV1` canonical JSON、原子写、未知版本拒绝。
- `search` 更新匹配 cell；`explain` 只读；`merge` 验证身份、去重和冲突。
- TTY progress 与非 TTY 稳定事件输出。

### S6 — 安全投影与编辑

- marker 可表示投影与完整覆盖授权。
- round-trip TOML 精确改写、语义 diff、注释/格式保留和幂等。
- `PREPARED → PROJECT_REPLACED → REPORT_CONFIRMED → COMMITTED` 恢复日志。
- `apply` 纯报告转换；`minimize` 仅在 search 成功后调用 apply。

### S7 — 端到端与发布门槛

- 安装后的 `pf` 和 `python -m pf` 等价。
- 最小本地包完成 `check → search → explain → apply`。
- 运行全套测试、coverage、构建/安装 smoke、静态架构检查和文档核对。

## 5. 验证矩阵

每个周期运行新增 focused test；每个切片结束至少运行：

```text
uv run pytest <focused tests>
uv run pytest
uv build
```

最终还验证：

- `uv run pf --help` 与 `uv run python -m pf --help`；
- 安装 wheel 后直接运行 `pf`；
- `rg` 检查 Rich/Cyclopts 导入所有权、无 msgspec、无禁用模块名；
- 报告 golden/canonical JSON、非 TTY、timeout、secret、原子写和重复 apply；
- 本地离线 fixture 的真实 `uv`/`ty`/测试路径；需要外部环境的验证单独列为未执行证据。
